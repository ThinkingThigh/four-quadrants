# 部署与运维说明

> 记录本项目的运行方式、开机自启配置，以及部署过程中踩过的坑。
> 最后更新：2026-10-12

---

## 一、环境要求

| 项 | 要求 | 原因 |
| --- | --- | --- |
| Node.js | **必须 ≥ 22.5** | 项目依赖内置的 `node:sqlite` |
| 第三方依赖 | **零** | 只用 Node 内置模块，无需 `npm install` |
| 操作系统 | macOS | 自启脚本基于 launchd |
| 监听地址 | `127.0.0.1` | 仅本机访问，不对外暴露 |

### ⚠️ node 版本是最大的坑

`node:sqlite` 是较新的内置模块，**很多版本没有**。本机实测结果：

| node 版本 | `node:sqlite` | 装了 pm2 |
| --- | :---: | :---: |
| v10 / v12 | — | ✗ |
| v14.5.0 | ❌ 不支持 | ✗ |
| v16.20.2 | ❌ 不支持 | ✗ |
| v18.17.1 | ❌ 不支持 | ✗ |
| v18.20.8 | ❌ 不支持 | ✅ |
| **v22.16.0** | ✅ **支持** | ✅ **有** |
| v22.21.1 | ✅ 支持 | ✗ |
| v23.2.0 | ❌ 不支持 | ✗ |

**结论：只有 `v22.16.0` 同时满足「支持 node:sqlite」和「装了 pm2」两个条件。**

注意 v18.20.8 也装了 pm2，但它的 node 不支持 `node:sqlite`——
这正是下面「坑 1」的成因。另外 **v23.2.0 意外地也不支持**，不要想当然认为版本越高越好。

快速自查某个 node 是否可用：

```bash
/path/to/node -e "require('node:sqlite')" && echo "可用" || echo "不可用"
```

## 二、日常运行

### 方式一：pm2 托管（推荐）

```bash
pm2 list                      # 查看状态
pm2 logs four-quadrants       # 实时看日志
pm2 restart four-quadrants    # 重启
pm2 stop four-quadrants       # 停止
pm2 delete four-quadrants     # 移除托管
```

配置在 `ecosystem.config.cjs`，日志在 `logs/`。

### 方式二：直接运行（调试用）

```bash
cd four-quadrants
node server/index.js
```

### 两种方式的区别

| | pm2 托管 | 直接运行 |
| --- | --- | --- |
| 终端关闭后存活 | ✅ | ❌（除非用 nohup） |
| 崩溃自动重启 | ✅ | ❌ |
| 开机自启 | ✅ | ❌ |
| 适合 | 长期使用 | 临时调试 |

## 三、开机自启配置

```bash
cd four-quadrants
sudo bash scripts/setup-pm2-startup.sh
```

脚本会做三件事：

1. 注册 launchd 自启项 → `~/Library/LaunchAgents/pm2.tal.plist`
2. 保存进程快照 → `~/.pm2/dump.pm2`
3. 自检并打印结果

### 验证是否配置成功

```bash
# 1. 看服务是否注册
launchctl list | grep -i pm2
#    能看到 com.PM2 就是成功

# 2. 看配置文件路径指向是否正确（关键！）
grep -A3 ProgramArguments ~/Library/LaunchAgents/pm2.tal.plist
#    必须指向 v22.16.0，不能是 v18

# 3. 看快照里的解释器
grep -o '"exec_interpreter":"[^"]*"' ~/.pm2/dump.pm2
#    必须是 v22.16.0/bin/node
```

### 手工重载配置（改完 plist 后）

```bash
launchctl unload ~/Library/LaunchAgents/pm2.tal.plist
launchctl load -w ~/Library/LaunchAgents/pm2.tal.plist
```

## 四、踩过的坑（重要）

### 坑 1：glob 展开按字母序，误选到 v18

**现象**：plist 里的 pm2 路径指向 `v18.20.8`，重启后应用起不来。

**根因**：脚本用

```bash
"$USER_HOME/.nvm/versions/node"/*/lib/node_modules/pm2/bin/pm2
```

glob 展开是**按字母序**的，`v18.20.8` 排在 `v22.16.0` 前面，所以被第一个选中。
更糟的是 v18 虽装了 pm2，但它的 node **不支持 `node:sqlite`**。

**修复**：按版本号倒序遍历 + 实测校验

```bash
for c in $(ls -1d "$USER_HOME/.nvm/versions/node"/*/ | sort -Vr); do
  N="${c}bin/node"; P="${c}lib/node_modules/pm2/bin/pm2"
  [ -x "$N" ] && [ -x "$P" ] || continue
  "$N" -e "require('node:sqlite')" >/dev/null 2>&1 || continue   # 实测
  PM2_BIN="$P"; break
done
```

**通用教训**：选路径时不要依赖 glob 的字母序，尤其是 `v18` / `v22` 这类版本号
——**字母序 ≠ 版本序**。永远用 `sort -V` 或显式校验。

### 坑 2：pm2 配置里写函数调用，导致 node 二进制被当脚本执行

**现象**：服务完全起不来，pm2 日志报

```
PM2 error: [PM2] Resurrecting PM2
/Users/tal/.nvm/versions/node/v22.16.0/bin/node:1
����
SyntaxError: Invalid or unexpected token
```

node 二进制文件被当成 JS 脚本去解析，所以报「无效字符」。

**根因**：我曾在 `ecosystem.config.cjs` 里写了个 `resolveNode()` 函数，
用 `execFileSync` 动态探测 node 路径。pm2 解析配置时把返回值处理错了。

**修复**：改回**静态字符串路径**

```js
const NODE = '/Users/tal/.nvm/versions/node/v22.16.0/bin/node';
// ...
interpreter: NODE,
```

**通用教训**：**pm2 配置文件里不要写函数调用或动态探测**。
`ecosystem.config.cjs` 会在 pm2 内部被反复解析和执行，任何非纯静态的写法都可能出问题。
需要动态逻辑就写进单独的脚本，不要放进配置文件。

### 坑 3：从 pm2 路径反推 node 目录，层级算错

**现象**：脚本生成的 plist 里 `PATH` 指向了错误目录。

**根因**：pm2 的安装路径是

```
<VERSION>/lib/node_modules/pm2/bin/pm2
```

想拿到 node 的 bin 目录（`<VERSION>/bin`）需要**向上三层**。
`NODE_BIN_DIR="$(dirname "$(dirname "$PM2_BIN")")/bin"` 只上溯了两层，
得到的是 `.../lib/node_modules/pm2/bin`。

**修复**：不要在事后反推，**在探测循环里直接把 node 路径一并记下来**：

```bash
if "$N" -e "require('node:sqlite')" >/dev/null 2>&1; then
  PM2_BIN="$P"
  NODE_BIN="$N"      # 一并记录，后续 dirname 只做一次
  break
fi
...
NODE_BIN_DIR="$(dirname "$NODE_BIN")"
```

**通用教训**：能直接记录的信息，不要事后靠路径拼接反推——层级一多就容易错。

### 坑 4：`pm2 save` 保存的是「当时的解释器路径」

`pm2 save` 快照同时记录了 `exec_interpreter`。如果换 node 版本后只重启、没重新 save，
开机恢复时仍会用旧路径。

**正确顺序**：

```bash
pm2 delete four-quadrants        # 1. 先删掉旧记录
pm2 start ecosystem.config.cjs   # 2. 用新配置重建
pm2 save                         # 3. 再存快照
```

### 坑 5：SQLite 必须单实例

`instances: 1` 不是可选项。SQLite 是单文件数据库，多实例会争抢写锁，
导致随机写入失败。已固定在 `ecosystem.config.cjs` 中，**不要改成 cluster 模式**。

## 五、故障排查

### 应用起不来

```bash
# 1. 看应用日志
tail -50 logs/err.log
tail -50 logs/out.log

# 2. 看 pm2 自己的日志（配置解析错误在这里）
tail -50 ~/.pm2/pm2.log

# 3. 确认 node 版本可用
/Users/tal/.nvm/versions/node/v22.16.0/bin/node -e "require('node:sqlite')"
```

### 端口被占用

```bash
lsof -ti:7788              # 查看占用进程
lsof -ti:7788 | xargs kill # 释放
```

### 服务无响应（502）

```bash
pm2 list                   # 看进程是否 online
pm2 restart four-quadrants # 重启
pm2 logs four-quadrants    # 看实时日志
```

### pm2 状态混乱（daemon 异常）

```bash
pm2 kill                                        # 停掉 daemon
rm -f ~/.pm2/pm2.pid ~/.pm2/rpc.sock ~/.pm2/pub.sock   # 清理状态文件
pm2 resurrect                                   # 从快照恢复
```

## 七、换机器部署清单

1. 装 Node 22.5+（推荐 22.16.0）
2. `npm install -g pm2`
3. 克隆代码（数据库不含在内，会自动新建）
4. 改 `ecosystem.config.cjs` 里的 `interpreter` 为本机 node 绝对路径
5. `pm2 start ecosystem.config.cjs`
6. `sudo bash scripts/setup-pm2-startup.sh`
7. 按第三节验证

> 第 4 步是关键。该路径与本机环境绑定，换机器必须改。
